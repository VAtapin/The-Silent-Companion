# Резервное копирование

Система защищает проект на трёх уровнях:

1. Документы сохраняются отдельными версиями и восстанавливаются со страницы документа.
2. Изменения карточки проекта, структуры фильма, каталогов, чек-листа и публичной страницы записываются с автором, временем и значениями «до/после». Восстановление доступно в разделе «История изменений».
3. Команда `backup:create` создаёт закрытый архив: согласованный дамп MySQL, все файлы Laravel Storage и манифест с SHA-256.

## Сервер

В `.env`:

```dotenv
BACKUP_PATH=/var/www/vhosts/the-silent-companion.com/private/backups
BACKUP_KEEP=14
MYSQLDUMP_PATH=/usr/bin/mysqldump
```

Каталог не должен находиться внутри `httpdocs/public`.

Ручное создание и проверка:

```bash
/opt/plesk/php/8.4/bin/php artisan backup:create
/opt/plesk/php/8.4/bin/php artisan backup:verify
```

В Plesk нужно создать задачу на 02:30 ежедневно:

```bash
cd /var/www/vhosts/the-silent-companion.com/httpdocs && /opt/plesk/php/8.4/bin/php artisan backup:create
```

Это одна задача в сутки. Запуск каждую минуту не требуется.

## Внешняя копия

Копия на том же сервере не защищает от потери всего сервера. Каталог `private/backups` необходимо включить в резервное копирование Plesk во внешнее хранилище. Для рабочего проекта рекомендуется хранить минимум 14 ежедневных локальных копий и отдельные еженедельные копии вне сервера.

## Восстановление всего проекта

Полное восстановление намеренно не выполняется кнопкой в веб-интерфейсе, поскольку оно перезаписывает всю базу. Перед восстановлением сначала проверяют архив через `backup:verify`, переводят сайт в maintenance mode, сохраняют текущую аварийную копию, импортируют `database.sql.gz`, распаковывают `storage.zip`, затем запускают `php artisan up`. Эту операцию должен выполнять владелец сервера.
